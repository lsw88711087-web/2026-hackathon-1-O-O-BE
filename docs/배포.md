# 배포 보충 — 가비아 콘솔 절차 & 세션 가이드 대조

**실제 배포 절차는 [`deploy/README.md`](../deploy/README.md)가 기준이다.** 이 문서는 두 가지만 담는다.

1. 가비아 관리콘솔에서 서버를 만들고 지우는 절차 (매뉴얼 요약)
2. 멋사 세션 배포 가이드(AWS EC2+ECR / Docker Hub 기준)를 **그대로 따르면 안 되는 지점**

---

## 1. 서버 생성 시 고를 값

| 항목 | 값 | 이유 |
| --- | --- | --- |
| OS | **Ubuntu 22.04** | `deploy/README.md`가 apt 기준이다 |
| 서버 타입 | High CPU 2vCore / 4GB / 트래픽 1TB | **제공 사양 초과 시 과금** |
| 스토리지 | 루트 100GB 단일 | 50+50으로 나누면 데이터 볼륨을 직접 마운트해야 한다 |
| 로그인 방식 | **비밀번호 방식** | 브라우저 터미널은 **SSH 키페어로 접속이 안 된다** |
| 공인 IP | 1개 | 팀당 지원 범위 |

생성 순서는 VPC → 서브넷 → 공인 IP → 서버. root 비밀번호는 "[가비아 클라우드] 서버가 생성되었습니다" 메일에 있다.

> 터미널 창을 닫아도 세션은 살아 있다. 끝나면 반드시 `exit`.
> `Ctrl+Alt+Del`은 로그아웃이 아니라 **재부팅**이다.

## 2. 보안그룹 인바운드

| 포트 | 소스 | 용도 |
| --- | --- | --- |
| 443 | 0.0.0.0/0 | HTTPS |
| 80 | 0.0.0.0/0 | 인증서 발급 + 리다이렉트 |
| 22 | 내 IP만 (또는 닫기) | 브라우저 터미널이 있어 없어도 된다 |

**8000번은 열지 않는다.** nginx가 앞에서 받고 gunicorn은 `127.0.0.1:8000`에만 바인딩한다(`deploy/oando.service`). 8000을 열면 HTTPS를 우회하는 평문 경로가 하나 생긴다.

## 5. 애플리케이션 서버는 gunicorn(WSGI)이다

⚠️ **uvicorn(ASGI)으로 띄우면 챗봇 스트리밍이 죽는다.**

`apps/chat/services.py`의 `respond()`가 동기 제너레이터인데, Django는 ASGI에서 동기
이터레이터를 만나면 전부 소비한 뒤 내보낸다.

```python
# django/http/response.py — StreamingHttpResponse.__aiter__
for part in await sync_to_async(list)(self.streaming_content):
    yield part
```

응답은 200으로 잘 오지만 조각이 흐르지 않고 **한 번에 도착한다.** 배포하고 나서야
알아채는 유형이다. `respond()`를 `async def` + `async for`로 바꾸기 전까지는 WSGI가 맞다.

SSE 응답 하나가 스레드 하나를 잡으므로 워커 클래스는 `gthread`를 쓴다.

## 6. 세션 가이드를 그대로 따르면 안 되는 지점

세션 자료는 일반 Django 기준이라 우리 코드와 어긋나는 곳이 있다. **이미 `deploy/`가 아래를 전부 반영해 두었다.**

| 세션 가이드 | 우리 코드에서는 | 왜 |
| --- | --- | --- |
| `gunicorn project.wsgi` (프로젝트명) | `gunicorn **config**.wsgi` | 우리 설정 폴더 이름이 `config`다. 여기서 제일 많이 막힌다 |
| `-e SECRET_KEY=...` | `DJANGO_SECRET_KEY` (둘 다 받게 고침) | 이름이 다르면 값을 넘겨도 조용히 개발용 기본키로 뜬다 |
| `USE_TZ = False` · `TIME_ZONE = Asia/Seoul` | **UTC 유지** | 명세가 `client_timestamp`·`server_received_at`을 ISO 8601 / UTC로 정의했다. 바꾸면 기존 이벤트 시각이 전부 어긋난다 |
| `ALLOWED_HOSTS = ['*']` 하드코딩 | `.env`의 `ALLOWED_HOSTS` | 코드는 한 벌만 두고 환경변수로 가른다 |
| 8000번 포트 직접 노출 | nginx 뒤 `127.0.0.1:8000` | 프론트가 HTTPS라 평문 API는 **mixed content로 차단**된다 |
| `--workers 2` + Redis 없음 | 워커를 2개 쓰려면 **Redis 필수** | 화보 폴링 상태가 LocMem이면 프로세스마다 캐시가 따로 논다(= 폴링 404) |
| `psycopg2-binary` | `psycopg[binary]` (3.x) | 이미 requirements에 있다 |
| sqlite를 컨테이너 안에 | 파일을 볼륨/호스트에 | 재배포마다 데이터가 날아간다 |

### Docker는 쓰지 않기로 했다

루트에 있던 `Dockerfile` · `docker-compose.prod.yml` · `Caddyfile` · `.dockerignore`는 삭제했다.

이유는 가비아 환경에서 도커가 주는 이득이 거의 없기 때문이다. 서버 1대·10일·배포 담당
1명이라 재현성보다 **재배포 속도**가 중요한데, systemd는 `git pull && systemctl restart`로
수 초면 끝나는 반면 도커는 로컬 빌드 → Hub 푸시 → 서버 풀로 몇 분이 걸린다. HTTPS도
결국 nginx + certbot이 필요해서 도커로 줄어드는 작업이 없다.

Postgres·Redis가 필요해지면 그 둘만 컨테이너로 띄우는 건 괜찮다. 앱은 systemd에 둔다.
